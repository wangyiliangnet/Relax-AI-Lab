# 迁入正式后端

本地实验服务只产生任务建议，真实任务仍由 iOS 选择后经现有保存入口写入；服务不替 App 创建数据库任务。

## 可迁移产物

- `contracts/*.schema.json`、iOS 请求/响应结构，以及成功/失败样例。
- 选定的教练 prompt、`prompts/contract.md`；模型输入还包括 Task JSON Schema 和 capabilities。
- `models.py`、`validation.py` 中的日期、循环、量化及 Pro 约束。Java 实现需独立校验，不能只依赖 JSON Output。
- 导出的调用记录，用作人工质量对比与回归样例。原始目标可能含私人数据，整理后再决定是否提交。

## 生产接入时替换

1. 模拟 profile 替换为可信用户身份和服务端订阅/权益来源，不信任客户端自报 Pro。
2. 对齐真实积分核算、扣费时机、幂等、并发、失败与取消语义。固定“一次一分”仅为本地联调账本。
3. 接入既有后端鉴权、错误码、超时、观测和密钥配置。
4. 确定正式 API 版本和路径，再更新 iOS Adapter；客户端预检查不是扣费授权，生成接口仍需校验权益。
5. 根据真实评估确定默认模型、token 上限和 prompt 版本。记录可重放请求，但不能保证再次调用会得到相同输出。

本期不做聊天追问、自动多轮修复、批量自动评测或生产账本。对比两个 prompt 时应保持目标、模型参数和权益一致；输入不同的历史记录不能当作严格 A/B 实验。
