日期：2026-11-16

状态：第一阶段以及第二阶段的批次归档、刷新恢复、全量历史分页与按用例配对比较已实施；字段级配置更新已完成；按最新要求，不实施修订号及并发冲突检测，当前方案范围已完成。配色收敛为浅色，移除暗色及跟随系统；保留现有接口和 App 会话规则。实施及测试范围见[验证记录](validation.md)。

## 现状与设计边界

### 已确认并继续遵循的决策

依据 [README](../README.md) 和 [设计决策](design.md)：

- 这是面向本地 Prompt 调优与 iOS 联调的实验工具；生产后端位于相邻 Relax-Backend。
- 保留 /deployment、/prompts、/simulate、/cases、/history、/costs 六个可直达、可刷新的地址；根路径目前进入 /simulate。
- 延续 GitHub Primer 风格；按最新要求仅保留浅色界面。
- App 会话保持打开即生成、成功默认全选、换批清空旧结果并排重、失败手动重试、关闭清空会话、模拟添加后隐藏空目标入口的规则。
- 目标、语言、Prompt 和模型参数在模拟会话中固定；批次固定启动时配置。当前浏览器中的目标会话与用例评测互斥。
- 服务每次最多执行一个生成请求，不自动重试。停止批次只停止后续用例；关闭会话不能承诺取消已经发送的上游请求。
- Prompt 版本不可覆盖；未保存的草稿允许用于 Web 实验，应用到服务前须保存新版本。
- Web 单目标模拟与 iOS 共用模拟账本；固定用例各自使用用例定义的模拟权益，不修改该共享账本。真实 token 费用独立核算。
- 未配置 key 时可查看、预览和使用 Mock；真实调用必须明确失败。浏览器只展示配置状态，不接收或显示 key。
- 起步与持续推进是建议分组；参数、日期、循环和量化展示以当前 App 契约为准。

### 需要优先解决的问题

以下为源码与界面走查得到的设计判断，需用真实工作任务验证优先级。

| 问题 | 现状依据 | 对流程的影响 | 对应方案 |
| --- | --- | --- | --- |
| 导航没有表达工作顺序 | 六项横向导航从部署开始，配置、评测、模拟并列 | 每次切页都要自己判断下一步 | 四项主导航与实验台子导航，部署移入环境入口 |
| 配置有多个作用范围 | 当前 Web 草稿、已保存版本、服务共享配置、运行快照同时存在；摘要主要显示版本、模型、provider | 容易误以为保存版本即对 iOS 生效 | 固定配置摘要与作用范围文案 |
| 一次保存耦合两件事 | Prompt 页同一按钮提交模型配置、会员身份、已用积分 | 调整实验配置可能同时改变共享模拟条件 | 分成“应用生成配置”和“应用模拟权益”两个明确动作 |
| 预览依赖另一个页面的目标 | Prompt 页预览读取模拟页中的目标；现有界面已有目标摘要，但目标编辑仍需跳转 | 在编辑 Prompt 时难以核对完整上下文 | 预览区展示目标、日期、语言摘要与返回入口 |
| 结果详情重复铺开 | 模拟、评测、历史和 A/B 分别组织指标、任务、评价与请求记录 | 信息层级、草稿保存和错误呈现难以保持一致 | 共用结果详情结构和评价草稿管理 |
| 配置锁定与服务占用不同 | 关闭生成中的会话后，本地会话消失，上游仍可能运行 | 页面看似可运行，下一次请求可能返回忙碌 | 单独展示已发送请求的活动状态，并与服务忙碌状态核对 |
| 批次缺少持续身份 | 当前批次在浏览器内存中，刷新丢失，新批次覆盖旧批次视图 | 回看同一批次或做版本配对需要手工整理 | 第一阶段明确边界和导出，第二阶段持久化批次 |
| 历史覆盖范围容易误读 | 历史接口只取最近 100 条，前端再分页；费用汇总覆盖全部记录 | 可能把近期检索结果当成全量 | 第一阶段显式标注范围，第二阶段服务端分页和筛选 |
| 配置读取与版本切换可能覆盖草稿 | 切版本、读取共享配置会重填编辑字段 | 未保存的改动需要额外记忆或复制 | 按版本保留本标签页草稿，替换动作显式表达 |

## 用户故事与验收条件

角色按工作职责划分，同一个人可以切换多个角色；不引入账户、权限或协作管理功能。

| 故事 | 角色与希望完成的事 | 使用入口及流程 | 完成条件 |
| --- | --- | --- | --- |
| S01 首次启动 | 本地部署者希望先确认工具能用，再决定是否接真实模型 | 环境检查 → Mock → 目标示例 → 打开会话 | 无 key 仍能完成 Mock 流程；全程有 Mock 标记；不形成质量通过结论 |
| S02 快速体验 | Prompt 调优者希望用一个目标判断建议是否有用 | 实验台 → 快速模拟 → 确认配置 → 生成 → 阅读任务 → 评价 | 阅读任务不必展开 JSON；能区分输出过滤、执行错误与人工评价 |
| S03 修改草稿 | Prompt 调优者希望编辑 Prompt 并检查最终请求 | Prompt 版本 → 编辑 → 选择预览上下文 → 预览 → 返回原工作页 | 预览不调用模型、不创建调用记录；显示当前目标和实际组装的请求 |
| S04 留下版本 | Prompt 调优者希望保存候选版本而不立即影响 iOS | 当前草稿 → 保存新版本 → 继续模拟或评测 | 新版本不可覆盖；保存成功后明确“已保存版本，服务共享配置未改变” |
| S05 验证 App 流程 | iOS 开发者希望检查生成、换批、重试和添加 | 快速模拟 → 生成 → 取消部分选择 → 换批或模拟添加 | 默认全选；换批失败不恢复旧结果；重试保留 refresh 与排重历史；添加只写 Web 模拟目标 |
| S06 固定场景回归 | 评测者希望用固定条件检查一个候选配置 | 固定用例 → 筛选和多选 → 核对配置及预计调用数 → 运行 | 本批配置固定；每条采用自身权益；Mock、预期拒绝、真实断言和执行错误分开统计 |
| S07 处理异常批次 | 评测者希望停止后续消耗并保留已完成结果 | 批次进度 → 停止后续用例 → 等待当前结束 → 查看未执行 | 不把未执行计为失败；不自动重试；已经发出的调用仍保留费用与结果 |
| S08 形成质量判断 | 评测者希望先看有问题的案例，再记录人工结论 | 批次结果 → 筛选断言失败或执行错误 → 单条详情 → 保存评价 | 自动断言与人工评价分开展示；失败原因能定位到字段或建议；评价草稿切换后保留 |
| S09 比较候选方案 | Prompt 调优者希望判断改版是否有收益 | 历史选 A/B，或第二阶段选择两批 → 核对上下文 → 对比 → 回到对应版本 | 显示输入、权益和参数差异；批次比较按相同用例及快照配对，缺失项单列 |
| S10 应用到 iOS | iOS 开发者希望把已验证版本交给本地 App | 已保存版本 → 查看共享配置差异 → 应用生成配置 → 环境连接 → App 发请求 → 历史筛选 iOS | 下次 iOS 请求采用新配置；不重置积分；记录来源与实际版本可核对 |
| S11 追溯问题 | 开发者希望重建一次异常调用 | 调用 ID 或历史记录 → 运行快照 → 原始返回 → 校验 → JSON 导出 | 历史查看不改当前实验；费用、指纹、输入和原始返回保持原始含义 |
| S12 控制开支 | 实验负责人希望知道费用范围，并维护后续适用单价 | 开支 → 全量汇总 → 版本明细 → 单价设置 | 未知不显示为零；失败可计费；调价和删除不改旧快照；费用与模拟积分始终分开 |

## 建议的信息架构

### 主导航与地址映射

桌面采用窄侧栏，保留四个主要目的地。实验台展开两个子入口；连接与环境放在侧栏底部，同时可从顶部环境状态进入。窄屏改成可换行的紧凑导航，不依赖横向滚动找到关键操作。

~~~text
Relax AI Lab                          环境状态 · 服务活动
├─ 实验台
│  ├─ 快速模拟                         /simulate，默认入口
│  └─ 固定用例                         /cases
├─ Prompt 版本                         /prompts
├─ 记录与对比                          /history
├─ 开支                                /costs
└─ 连接与环境                          /deployment，辅助入口
~~~

“实验台”是导航分组，不要求用户先创建一个实验项目，也不新增必填的实验名称。保留页面直达与浏览器前进、后退；从历史或费用看完详情后，能回到原筛选与选择位置。

### 页面共同骨架

~~~text
┌ 导航 ───────┬ 页面标题与简短用途 ─────────── 环境 / 服务状态 ┐
│ 实验台      │ 当前试验配置：版本 · 草稿标记 · 模型 · 调用方式 │
│  快速模拟   │ 服务共享配置：一致 / 有差异      查看配置差异   │
│  固定用例   ├ 当前页操作区：一个主操作 + 条件说明 ───────────┤
│ Prompt 版本 │                                                │
│ 记录与对比  │ 当前页的输入、列表或结果                        │
│ 开支        │                                                │
│             ├ 活动条：本浏览器运行状态 / 服务忙碌 / 返回活动 ─┤
│ 连接与环境  │                                                │
└─────────────┴────────────────────────────────────────────────┘
~~~

配置摘要用于模拟、用例和 Prompt 页；历史详情显示“该次运行快照”，开支显示自身统计范围，避免把当前试验配置误套到历史数据。活动状态在所有页面一致可见。

## 配置及状态模型

### 统一四个概念

| 名称 | 包含内容 | 生效对象 | 页面表达 |
| --- | --- | --- | --- |
| 当前试验配置 | 所选版本、可选草稿、provider、model、temperature、maxTokens | 从本浏览器发起的下次模拟或评测 | “仅用于本浏览器的后续实验”；草稿单独标记 |
| 已保存 Prompt 版本 | 不可覆盖的业务 Prompt 文本 | 可被任何客户端选择；保存本身不改变服务默认配置 | “版本已保存”；提供“去评测”和“应用到共享服务” |
| 服务共享配置 | 服务默认生成配置，以及单独管理的模拟权益账本 | iOS 和未显式传配置的请求；共享账本也用于 Web 单目标模拟 | 展示真实生效值和与当前试验配置的差异 |
| 运行快照 | 实际输入、完整 Prompt 指纹、参数、权益、原始返回、校验、用量及价格快照 | 单次历史记录；批次中每条记录也各有快照 | 不可编辑；允许复制为新的试验配置 |

业务 Prompt 版本名与实际完整请求指纹不同。固定契约和 Schema 也进入系统消息；相同版本名不保证不同时间的完整 Prompt 指纹相同。对比时同时检查版本、草稿标记和实际指纹。

### 操作语义

- “保存新版本”：只创建 Prompt 版本；不写服务默认模型或账本。
- “应用生成配置到共享服务”：只计划修改 provider、model、采样参数和已保存的 promptVersion；操作前在同一区域展示前后差异、作用对象和按钮，不增加重复确认弹窗。
- “应用模拟权益”：在连接与环境中修改会员身份和已用积分；清楚说明 Web 单目标模拟与 iOS 共用，固定用例不使用这个账本。
- “查看共享配置”：只读取；如要替换本地编辑内容，使用独立动作“用共享配置替换当前试验配置”，替换前保留本标签页草稿。
- “复制为当前试验”：从历史生成新草稿，须由用户明确操作；不修改历史、不打开会话、不自动调用模型。

PATCH /lab/profile 已支持字段级更新，生成配置和模拟权益分别只提交本次修改的字段；嵌套 options 也保留省略的值。原 GET/PUT 完整 Profile 接口保持兼容。根据用户最新调整，不实施修订号校验和并发冲突处理。

### 配置锁定与活动状态分开

1. 模拟会话打开后，继续固定目标、语言与生成配置；评测运行时继续固定本批配置。
2. 保留当前浏览器内模拟与批次互斥，禁用操作旁直接给出“返回会话”或“查看评测”。
3. 关闭会话后立刻丢弃会话建议、选择和排重；已经发出的请求仍在活动条中显示，直到该请求完成或查询服务状态确认空闲。迟到响应只更新活动与历史，不重建会话。
4. 服务 busy 与本浏览器活动分别表达；外部客户端造成的忙碌只显示“服务正在处理请求”，不臆测操作者或任务进度。
5. 当前服务锁覆盖单次请求，并不预留整个浏览器批次；iOS 或其他浏览器可能在两条用例之间发起请求。遇到 409 按执行错误停止后续，不悄悄跳过或重试。
6. 页面内导航不结束会话或批次。离开网页的原生提示只作补充，不能作为状态持久化保证。

## 对应使用流程

### 首次启动与快速体验

~~~mermaid
flowchart LR
    A[进入快速模拟] --> B{环境检查}
    B -->|未配置 key| C[显示 Mock 可用]
    B -->|已配置 key| D[选择 Mock 或 DeepSeek]
    C --> E[载入目标示例并核对配置]
    D --> E
    E --> F[打开会话并检查权益]
    F --> G[首次生成并默认全选]
    G --> H[阅读建议及校验]
    H --> I[评价或模拟添加]
~~~

未配置 key 且选择真实调用时，按钮旁提示缺失配置并链接到环境说明；服务端继续保留明确失败的校验，禁止静默切成 Mock。key 已配置只表示本机存在配置，不表示模型连接已验证；检查 /health 不标为“模型连通成功”。

### 单目标体验与 App 会话

~~~mermaid
stateDiagram-v2
    [*] --> 准备目标
    准备目标 --> 检查权益: 打开会话
    检查权益 --> 首次生成: 权益允许
    检查权益 --> 积分不足: 权益拒绝
    首次生成 --> 待选择: 成功并默认全选
    首次生成 --> 生成失败: 调用失败
    待选择 --> 换批生成: 换一批并清空当前结果
    换批生成 --> 待选择: 成功并累计排重标题
    换批生成 --> 生成失败: 失败不恢复旧结果
    生成失败 --> 原模式重试: 手动重试
    原模式重试 --> 待选择: 成功
    原模式重试 --> 生成失败: 失败
    待选择 --> 已添加: 模拟添加所选任务并关闭会话
    已添加 --> 准备目标: 清空模拟任务
    积分不足 --> 准备目标: 关闭会话后调整模拟权益
    待选择 --> 准备目标: 关闭会话
~~~

所有打开状态都可以关闭；检查权益或生成中关闭时同样返回准备目标，但活动条继续追踪已发送请求。重试使用原 generationMode 和排重集合；不把失败的 refresh 变成 initial。关闭后重新打开同一目标才回到 initial。

模拟添加保留“只写页面内模拟目标”的说明。成功提示与模拟目标任务数相邻，不把 Web 模拟添加称为“已保存到 App”。

### Prompt 迭代与批量回归

~~~mermaid
flowchart LR
    A[编辑 Prompt 草稿] --> B[预览最终请求]
    B --> C[单目标试跑]
    C --> D[关闭模拟会话]
    D --> E[保留配置并选择固定用例]
    E --> F[核对本批配置及预计调用数]
    F --> G[串行执行]
    G --> H[查看分类结果与人工检查项]
    H --> I[保存新版本或继续修改]
    I --> J[保留用例选择并运行下一批]
    J --> K[比较结果]
~~~

第一阶段沿用内存中的最新批次，开始下一批前提示“当前批次视图将替换，调用记录仍保留”，提供导出入口；不得暗示旧批次仍可按批次 ID 恢复。第二阶段增加批次归档后，再开放“与上一批比较”。

运行前显示“已选 N 条，预计最多 M 次上游调用”，M 排除本地即可判定为预期输入拒绝的用例；保留“实际以执行结果为准”。不能用调用次数直接换算精确费用；缺少 token 依据时不展示虚构的金额预算。

### 结果比较与选择

第一阶段把当前结果的“设为 A”“设为 B”直接接到已有历史 A/B 对比，进入时携带选中的调用 ID。可以在记录详情发起比较，无须重新在下拉框中寻找。

第二阶段的批次比较按以下条件处理：

1. 以 caseID、用例输入与断言快照标识匹配场景；同 ID 但快照不同的记录标为“口径变化”，不直接合并统计。
2. 同一批次若重复运行同一用例，明确选择某次 attempt，默认展示最新一次且标记，不把多次采样混成一对。
3. 只对完整配对且口径一致的用例计算共同样本结果，A 独有、B 独有、未执行与错误分别列出。
4. 比较 Prompt 时固定模型与采样参数；若用户主动比较模型或参数，将差异标为实验变量，不把全部差异笼统视为异常。
5. 相同输入和参数的一次采样也可能波动；页面显示实际运行次数，不把单次结果表述为稳定胜率。
6. 优先展示“新增失败、已修复、仍失败、人工待检查”，随后展示任务内容、耗时、tokens 与已知费用。Mock 不参与质量通过率。

### 应用到服务与 iOS 联调

~~~mermaid
flowchart LR
    A[选定已保存版本] --> B[核对共享生成配置差异]
    B --> C[应用生成配置]
    C --> D[连接与环境复制 Xcode 配置]
    D --> E[手机健康检查并从 Xcode Run]
    E --> F[App 发起生成]
    F --> G[历史按 iOS 来源核对运行快照]
~~~

生成配置与模拟权益使用两个区域、两个保存动作。应用配置后只说明“后续请求生效”；不会改写正在进行的运行快照，也不会把浏览器草稿自动发布到 iOS。

## 页面设计

### 实验台中的快速模拟

- 顶部展示当前试验配置及草稿状态，提供“修改配置”；携带返回位置，编辑后能回到原目标。
- 桌面左侧约 320px 为目标输入，右侧为任务建议与结果。目标 ID、请求日期及排重标题放进“会话上下文”；标题、备注、日期和 App 语言保留直接编辑。
- 会话打开后目标输入显示只读摘要与锁定原因。会话主操作随阶段变化：打开、等待、模拟添加、失败重试；“换一批”和“关闭会话”作为次操作。
- 任务卡默认显示标题、备注、实际日期、循环、量化目标；计算方式、重置周期等仍可展开。沿用起步与持续推进名称。
- 任务区下方放结果摘要与详情页签，不在首屏同时铺开全部校验、评价表单和原始 JSON。
- 部分过滤仍可成功；摘要显示“保留 N 条，过滤 M 项”，点开定位具体原因。不能把过滤项数量简单等同于被过滤任务数。
- 模拟添加后展示目标下的任务与清空入口，保持 App 空态入口规则。

### Prompt 版本

- 主区为编辑器，侧区为模型参数；保存新版本按钮与版本名输入紧邻，编辑区顶部显示“基于哪个版本”和草稿状态。
- 将“去快速模拟”“用固定用例评测”放在同一后续动作组，均沿用当前试验配置；有活动锁定时给出返回入口。
- 请求预览分为上下文摘要和最终请求，固定契约及 Schema 默认折叠，保留完整复制与 JSON 查看器。
- 预览上下文明确来自当前模拟目标，提供“编辑目标后返回”；切换固定用例上下文属于后续增强，应调用对应的固定输入与权益，不能沿用共享权益冒充该用例。
- 共享生成配置改成紧凑的独立区域，展示服务生效版本、与当前配置的差异和应用动作；模拟权益移至环境页。
- 按基础版本保留本标签页草稿。切版本时保存上一份草稿，载入相应版本草稿；“放弃此草稿”作为明确动作。

### 实验台中的固定用例

- 用例列表和详情维持双栏，区分“勾选以运行”和“点击以查看”；显示已选总数及其中被筛选隐藏的数量。
- 未运行时顶部只显示配置摘要、选择数量和主操作；开始后同一区域变成进度、当前用例、分类数量及停止后续操作。
- 运行前直接展示调用方式、配置是否草稿、固定权益规则和预计调用数。Mock 使用“运行 Mock 联调”，真实模型使用“运行所选用例”，避免使用者忽略调用方式。
- 运行后默认定位首个需要处理的结果；提供“全部、断言失败、执行错误、未执行、待人工评价”筛选，保持原用例选择不变。
- 人工检查项放在任务结果上方；自动断言、服务业务结果、人工评价分别呈现。自动断言通过但整批无有效建议等情况保留双重状态。
- 新批次不静默丢弃未保存评价草稿。第一阶段按 runID 保存本标签页草稿，跨模拟、用例与历史页共用。
- 运行中允许正常浏览其他页面；活动条可一键返回当前评测。

### 记录与对比

- 浏览模式采用摘要列表与单条详情，保留搜索、状态、来源筛选；第一阶段标题明确“最近 100 条调用”，前端分页不称为全量分页。
- 摘要持续显示来源、调用方式、版本及草稿标记、运行状态和人工评价；不以 good 默认值暗示已经评价。
- 共用结果详情：概览、任务建议、校验、人工评价、请求与响应；有结果即能“加入 A/B 对比”，无需先切页签再找记录。
- 比较前显示输入、日期、语言、generationMode、排重集合、会员身份、模型及采样差异；目标 ID 不同本身不证明业务输入不同。
- A/B 的任务按建议分组并排阅读；不凭展示序号断言两条建议互相对应。窄屏依次显示 A、B，并重复版本名，避免失去上下文。
- 从历史“复制为当前试验”时检查活动锁，复制目标、语言与生成配置并保留原目标 ID；新会话依然从 initial 开始，不带入旧会话排重，不自动发出请求。历史草稿的固定契约或 Schema 已变化时，提示从原始记录手动核对。

### 开支

- 默认展示费用概览与版本明细；单价维护放进“单价设置”次级页签，减少日常查看的文本负担。
- 概览明确统计全部记录，并分别显示已知估算费用、未知费用调用数、进行中、明确未计费。所有金额继续使用服务返回的 Decimal 字符串。
- 单次详情沿用统一费用摘要，可查看调用开始时的价格、时段和历史回填标记。自动断言失败或服务失败并不等于免费。
- 第一阶段按单条记录跳转详情；按某个费用分组查看全部原始调用需第二阶段全量历史查询能力，不能用最近 100 条记录假装覆盖全量。
- 单价编辑先选模型、上游地址对应的配置和时段，再填写价格；删除按钮明确显示影响“后续调用”，缺价时可能变为未知。
- 沿用生成中禁止改单价的约束，收到 409 时显示服务忙碌并允许手动刷新。官方单价日期展示为现有配置来源日期，不在本轮重新宣称价格已核对。

### 连接与环境

- 上半区用检查顺序组织：服务可达 → 监听与可选地址 → key 配置状态 → Xcode 配置 → 手机端检查；明确哪些能自动判断、哪些需人工确认。
- 继续提供 LAN 地址与复制环境变量，避免将 0.0.0.0 当成连接 URL。复制 key、粘贴 key、显示 key 均不进入浏览器流程。
- 下半区独立管理共享模拟权益，显示会员、已用、总额度与每次扣除规则。积分是模拟业务条件，不与人民币费用合并。
- 保留当前受信局域网、本地调试的定位，不扩展生产用户管理或真实订阅功能。

## 结果与异常的统一表达

结果详情由同一组件组织，但每次显示的都是所选运行的快照；切换查看不会改变当前模拟会话或批次。

| 层级 | 主要内容 | 默认展开规则 |
| --- | --- | --- |
| 运行概览 | Mock 或真实调用、服务状态、时间、版本及草稿、耗时、token、费用 | 始终可见 |
| 任务建议 | 起步、持续推进、实际日期、循环及量化 | 有结果时默认展开 |
| 自动检查 | 参数过滤、用例断言、预期输入拒绝、业务无有效建议 | 有异常时展开并定位 |
| 人工评价 | 未评价、可用、需调整、不可用，备注及保存状态 | 用户进入时展开；草稿不当作已保存 |
| 原始记录 | 请求、完整 Prompt、上游返回、App 响应、价格快照、导出 | 默认折叠 |

| 状态或错误 | 用户可见信息 | 可执行操作 |
| --- | --- | --- |
| 无 key | “未配置 DeepSeek key；可使用 Mock” | 查看环境说明；显式选择 Mock；服务端仍拒绝真实调用 |
| 无可选任务 | “尚未选择任务” | 选择任务后启用模拟添加 |
| 目标或参数非法 | 字段旁说明具体原因，保留所有输入 | 修正字段；输入拒绝不显示成模型质量失败 |
| 积分不足 | 显示共享模拟权益与剩余值 | 关闭会话后前往模拟权益设置 |
| 409 忙碌 | 区分本浏览器活动和服务忙碌 | 返回活动或手动刷新状态；不自动重试 |
| 502 输出失败 | 保留调用 ID、过滤与原始返回 | 查看校验、调整 Prompt、手动重试 |
| 504 超时或连接异常 | 说明调用结果或费用可能未知 | 查看历史记录；用户决定是否再次调用 |
| 部分建议被过滤 | 显示有效建议和过滤项数，保留服务成功状态 | 查看被过滤原因后评价 |
| 预期输入拒绝 | 显示“按预期拦截，未调用模型” | 查看固定输入与断言 |
| 批次已停止 | 已完成、错误、未执行分别显示 | 导出或重新选择后发起新批次 |
| 页面刷新 | 当前会话与内存批次不恢复，调用记录可查 | 恢复编辑草稿和用例选择；不恢复运行状态、不重发请求 |

## 状态保存与响应式规则

### 第一阶段的保存范围

| 状态 | 站内切页 | 刷新同一标签页后的建议行为 |
| --- | --- | --- |
| 当前试验配置和按版本的 Prompt 草稿 | 保留 | sessionStorage 恢复草稿，显式标记“已恢复草稿” |
| 目标输入、用例选择、筛选及返回位置 | 保留 | 恢复可编辑输入和选择 |
| 模拟会话、建议选择、排重历史、已模拟添加任务 | 保留现有生命周期 | 不恢复 App 会话或模拟任务，不自动发出请求 |
| 评测批次执行状态 | 导航中继续 | 不恢复为运行中；提示去历史查看已发调用 |
| 人工评价草稿 | 按 runID 在各页共用 | 可恢复为“未保存”；只有用户保存才写后端 |
| 运行记录与服务配置 | 由服务持久保存 | 重新读取服务，不以浏览器缓存覆盖 |
| 配色 | 统一浅色 | 忽略旧配色偏好 |

浏览器只存本地编辑内容与选择，不存 API key、请求鉴权头或真实运行的完整原始返回。恢复本地草稿不代表同步到其他同事的浏览器。第二阶段的批次恢复只恢复归档视图，未经用户启动不继续调用。

### 布局与可访问性

- 1200px 以上使用约 184px 侧栏和输入／结果双列；800–1199px 保持主导航紧凑，减少边距；800px 以下折叠为单列。
- 桌面操作区可吸顶；窄屏避免多条吸顶区挤占结果，使用正常文档流和清晰的返回定位。
- 基础字号 14px，正文与输入可读；主标题约 22px，区域标题约 15px。正文不依赖浅灰小字承载关键约束。
- 使用语义化链接、按钮、原生选择框和复选框；状态同时用文字和颜色表达。执行进度用 aria-live 通知，避免重复播报每次重绘。
- 每个操作组只设一个主要按钮；选择、查看、开始、保存、应用使用不同动词。危险操作不只放垃圾桶图标。
- 320px、390px、1024px、1440px 均不出现页面级横向溢出；复杂表格允许独立横向阅读，JSON 长字段可换行或在查看器内部处理。
- 浅色沿用当前语义色：主操作、链接、错误和成功保持稳定；Mock 使用独立文字标识，不借用质量成功状态。

## 实施顺序与验收

### 第一阶段 界面与流程整合

1. 重组导航和页面共同骨架，保留六个路径及现有生成行为。
2. 建立统一试验配置摘要、草稿提示、共享配置差异和返回来源。
3. 把生成配置应用与模拟权益应用分开，通过局部更新保留未提交字段。
4. 整理快速模拟与固定用例的操作区，增加输入就地校验、状态定位与结果筛选。
5. 共用结果详情与评价草稿；从单次结果直接选择 A/B，增加范围与可比性提示。
6. 恢复本标签页编辑草稿、筛选和用例选择；刷新不重建会话、不重发调用。
7. 调整开支信息层级，单价设置降为次级入口；历史明确最近 100 条范围。

可复用现有 /lab/profile、/lab/prompts、/lab/preview、/lab/runs、/lab/cases、/health、/lab/connection 与价格接口。前端内部可抽取配置状态、活动状态、结果详情、评价草稿和导航返回信息，继续使用原生 ES modules，不为本次整合引入构建框架。

阶段完成须验证：六页直达及前进后退；导航保留草稿；所有 App 会话规则；部分过滤与无结果；会话关闭后的迟到响应；浏览器内互斥和外部 busy；Mock 与真实断言区分；停止后当前请求完成；共享配置应用不重置积分；刷新恢复编辑但不调用；A/B 上下文差异；费用未知；系统暗色下仍显示浅色，以及窄屏布局。

### 第二阶段 批次与全量记录闭环

- 归档 EvaluationBatch：批次 ID、配置快照、用例及断言快照、状态、每条判定与可选 runID、开始结束时间、停止原因。预期输入拒绝没有 runID 时也能保存。
- 持久化单条完成与未执行状态，刷新后能读取归档。浏览器异常退出后将批次标为中断并与已有调用记录核对，不把尚未发出的用例自动补跑。
- 若要脱离页面继续执行，需要单独设计服务端串行执行器、停止信号和中断恢复；不能仅靠存储一个 batchID 宣称支持后台运行。
- 已提供批次列表、按同一输入口径配对比较和批次导出。每批每例固定一次，attempt=1；重跑创建新批次，不提供同一批内重复采样或覆盖。
- /lab/runs 增加服务端分页和筛选，返回覆盖范围与总数；摘要补充 promptEdited、promptHash、caseID、判定及 batchID，避免前端为筛选批量读取完整 Prompt。
- 共享配置已增加字段级更新。修订号与并发冲突检测按用户最新要求取消。

新增数据放进现有 Git 忽略的 data/ 存储，HTTP 接口名称和持久化结构另行评审；不改变 iOS 的业务请求及任务响应契约。

### 评审与验证任务

| 验证任务 | 成功判据 |
| --- | --- |
| 无 key 首次打开 | 能直接完成 Mock；清楚知道未进行真实质量评测 |
| 改 Prompt 后试跑两轮 | 无需重复输入目标；能指出当前草稿、已保存版本与服务版本 |
| 筛选并运行一组选定用例 | 能确认隐藏选择、固定权益和本批配置；能找到失败与未执行 |
| 生成中离开、关闭会话或停止批次 | 活动状态不失真，不误以为上游已取消，不自动再次计费调用 |
| 把候选版本应用到 iOS | 正确应用生成配置；不意外修改模拟权益；能从 iOS 来源记录核对 |
| 查看旧记录和费用 | 能识别最近记录与全量开支范围；未知费用不会被理解成零 |

记录任务完成情况、回退次数、配置作用范围误判和未保存内容丢失次数。先用当前界面建立基线，再用同样任务比较；本提案不声称已经获得效率提升比例。

### 建议采用与待定事项

建议直接以“四项主导航、实验台双入口、辅助环境入口、配置摘要、统一结果详情”作为首轮方案，实施范围选第一阶段。保留 Mock 与真实调用、模拟积分与人民币费用、当前会话与历史运行的独立语义。

第二阶段需明确：批次只归档还是由服务端接管执行；是否需要跨浏览器共享草稿；是否支持同一用例多次采样比较。默认选择先归档、不共享草稿、单次配对并明确采样次数，避免让首轮界面整合依赖完整实验管理系统。
